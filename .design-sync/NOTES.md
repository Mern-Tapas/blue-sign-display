# Design sync notes (BlueSigns → Claude Design)

## How this repo is packaged
- This is a Next.js **app**, not a published package. `design-system/` is a thin package wrapper
  (`@bluesigns/ui`) that exists only for the sync:
  - `design-system/index.ts` is GENERATED by `design-system/scripts/gen-entry.mjs` (every component
    under `components/` except `components/docs/`, plus stores, helpers and `sampleData`). Re-run it
    (part of `buildCmd`) whenever components are added/renamed. Name collisions are aliased in its
    `RENAME` map: admin `FilterBar` → `AdminFilterBar`, admin `PaymentStatus` → `AdminPaymentStatus`.
  - `design-system/tsconfig.json` is the bundle's path map (`cfg.tsconfig`): `@/*` → repo root, and
    `next/link`, `next/image`, `next/navigation`, `@/public/logo.jpg` → `design-system/shims/`.
    Exact keys must stay ABOVE the `@/*` wildcard (the converter's paths plugin matches in order).
  - `design-system/scripts/build-css.mjs` compiles `design-system/styles.css` (tokens + Tailwind v4 via
    the app's own `@tailwindcss/postcss`) → `design-system/dist/styles.css` (gitignored, = `cfg.cssEntry`).
    It scans `components/`, `lib/` and `.design-sync/previews/`, plus an `@source inline(...)` safelist
    of layout/token utilities for designs the agent writes.
  - Fonts: Geist / Geist Mono woff2 files were copied from the app's `next/font` build output into
    `design-system/fonts/` with `fonts.css` (`cfg.extraFonts`). `styles.css` maps
    `--font-geist-sans/-mono` (normally set by next/font on `<html>`) to those families.
  - Logo: `shims/logo-128.png` is `public/logo.jpg` scaled to 128px (bundle loaders don't handle .jpg).
- Build order: `buildCmd` (gen-entry + build-css) → `package-build.mjs` → `package-validate.mjs`.
- Theme: tokens default to light on `:root`; dark mode = `data-theme="dark"` on an ancestor.
- Product/avatar images are remote Unsplash URLs (need network at render time).
- `design-system/tsconfig.json` must not contain `//` anywhere (not even in a JSON "comment" key): the converter strips `//...` to end of line before JSON.parse, and a parse failure silently drops the whole path map (Next shims stop applying).

## Preview authoring (learned on the solo set: Button, ProductCard, Dialog)
- Previews import ONLY from `@bluesigns/ui` (components, `icons`, `sampleData`, stores/helpers). Importing
  `@/…` or `lucide-react` directly bundles a second copy (and a second store instance).
- Sources to port from, in order: `components/docs/demos/*.tsx`, `app/design-system/*/page.tsx`, then the
  component source. Sample data: `sampleData.products`, `sampleData.addresses`, `sampleData.adminOrders`…
- Open overlays: `<Dialog defaultOpen>` + `onOpenAutoFocus={(e) => e.preventDefault()}` (otherwise the first
  field is focused/selected in the screenshot) + `onInteractOutside={(e) => e.preventDefault()}`.
  Overlay components have `cfg.overrides.<Name> = {cardMode: "single", viewport: "900x700"}` pre-set; the
  FIRST export is the primary story unless `primaryStory` is set.
- Tailwind classes in previews must already exist in `design-system/dist/styles.css` (component classes +
  the `@source inline` safelist) until the next `build-css` run; use `style={{ maxWidth: … }}` for one-off sizes.

## Known render warns
- `[FONT_MISSING] "Geist Fallback", "Geist Mono Fallback"`: these are next/font's metric-adjusted
  `src: local(Arial)` fallbacks (declared in design-system/fonts/fonts.css); there is no file to ship.
  The real Geist / Geist Mono woff2 files do ship. Accepted.

## Intrinsic sizing gotchas (found auditing the storefront, 2026-09-23)
- **`Field` needs `min-w-0`.** A `Field` is nearly always a grid or flex item. Without `min-w-0` its
  *minimum contribution* is content-based, so one long unbreakable string in its control (a selected
  product title, an email, a file name) sizes the whole track and pushes the page past the viewport.
  `/contact?model=<a long catalogue title>` measured `scrollWidth` 499 vs `clientWidth` 375 at 390px
  before the fix. `min-w-0` on the *control* is not enough — the grid item is what needs it.
- **`truncate` does nothing on a flex container.** `text-overflow: ellipsis` only applies to a block
  container, so `Select`'s trigger clipped its value mid-glyph with no "…". The value now sits in its
  own `min-w-0 truncate` block inside the flex row. Note `SelectPrimitive.Value` does **not** forward
  `className`, so the truncation has to live on a wrapper you render yourself.
- **Put list separators *before* each item, not after.** `Breadcrumbs` wraps (`flex-wrap`), and a
  trailing chevron dangles at the end of a wrapped line — the same defect the `meta-list` utility
  exists to avoid. Rendering the chevron for `i > 0` means a wrap always breaks before it.
- **Bare inline links are not touch targets.** The footer's links measured 45x18-98x18px: under the
  WCAG 2.5.8 floor (24x24) and far under `--hit-min`. Links that sit on their own row get a row
  token (`min-h-row-sm`); links inline in a sentence get `hit-area relative` instead, which grows the
  target on coarse pointers only and never moves the text.
